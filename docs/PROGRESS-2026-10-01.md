## Phase A — Fix broken runtime uploads

Root cause (proven): Next standalone in production snapshots `public/` **once at boot**
(`next/dist/server/lib/router-utils/filesystem.js` → `publicFolderItems`); the live-fs check is
`dev`-only. Files uploaded after boot 404 through the app router → image optimizer 400 → cards broken.
External `/uploads/*` is masked by nginx (`alias`), which is why some URLs "work".
Fix = app route handler serves live fs for paths missing from the boot snapshot. No DB/config changes.

## Discovered during execution

- *(A1)* `src/proxy.ts:134` matcher gap for non-image upload extensions (handled in A2b).
- *(B6)* Dev origin gotcha: browse via `localhost` only — `127.0.0.1` is 403-blocked by Next 16 `block-cross-site-dev.js` (kills hydration/HMR). See B6b row.
- *(B6)* `document.cookie` can't be set inside a React component render — `language-switcher.tsx` uses a module-scope `setLocaleCookie` helper called from the change handler.
- *(D8)* **Stale Turbopack cache**: wiping `.next/dev` alone is NOT enough — persistent cache in `.next/cache` kept serving pre-D4 client bundles (`saveOffer` crashed reading `OFFERS.CREATE` of undefined, no POST issued) and pre-D7 i18n (hydration mismatch on `manageHomepage`). Fix: full `Remove-Item -Recurse .next` + restart dev. Post-`prisma generate` / post-edit restarts should assume this.
- *(D8)* **Browser HTTP cache can serve stale dev CSS** (203KB vs server 207KB — new utilities like `bottom-24`/`bg-obsidian/75` "missing" though present server-side). `navigate ignoreCache` didn't bust it; do `fetch(cssHref,{cache:'reload'})` then `location.reload()` — or verify server CSS directly with `Invoke-WebRequest` before blaming Tailwind generation.
- *(C1)* `/etc/nginx/sites-enabled/mysticegypt` is a **regular file**, not the usual symlink to `sites-available` — editing only `sites-available` + reload changes nothing (active config stayed 10M until the enabled copy was edited too). The two had also drifted (`/_next/image/` vs `/_next/image` — the enabled/no-trailing-slash variant is the correct live one; the available copy with slash would NOT match `/_next/image?url=…`). Files synced 2026-10-02; always grep/reload-check `sites-enabled`. Also: embedding `$?` in PowerShell→ssh double-quoted strings silently corrupts the remote command (it got eaten into an `echo` string) — keep remote commands free of `$` or single-quote them.
- *(X1)* **Turbopack whole-project tracing → 521 MB bundle:** dynamic `fs.stat`/`fs.readFile` in `src/app/uploads/[...path]/route.ts` (Phase A) made `next build` trace the entire project into `.next/standalone`. Fixed with the warning-suggested `/*turbopackIgnore: true*/` on both calls → 40.2 MB. Any future dynamic fs read in app code must use the same opt-out or be statically scoped.
- *(X1)* `scripts/package-release.ps1` must run under **pwsh (PS7)** — Windows PowerShell 5.1 mis-decodes the UTF-8 em-dash in a `throw` string and fails with a parse error before building.
